## Task 2: leaderboard forecast
**Declared values for the submission:**

| | Value | Where it comes from |
|---|---|---|
| P (trainable parameters) | **152,965** | 5 ensemble members × 30,593, `count_params` in `task2/autoformer/model.py` |
| E (training epochs) | **10** | 5 members × 2 epochs, read back from each member's `log.jsonl` |

Both are recorded in `results/t2/final/manifest.json`. `make_submission.py` checks them against the rebuilt models and the training logs before it writes anything.

**Final model:**
- An encoder–decoder Autoformer with progressive series decomposition and Auto-Correlation: d_model 32, 4 heads, 2 encoder layers and 1 decoder layer, d_ff 64, moving-average kernel 25, k = floor(ln L).
- Input length 720 and label length 168. The ten external covariates are fed to the decoder over the label window and the 168 forecast steps.
- Five seeds (0–4), each trained for 2 epochs on all 43,656 observations. The forecast is their mean, clamped at 0.

### Layout
| Path | What it does |
|---|---|
| `task2/guards.py` | leakage and reporting guards, imported first by every script |
| `task2/data.py` | loading, scaling on training rows only, validation origins, metrics; `python -m task2.data` scores the naive baseline |
| `task2/autoformer/` | the Autoformer (`layers.py`, `model.py`) |
| `task2/train.py` | trains one model; validation runs score 78 origins every epoch |
| `task2/eda.py` | ACF and periodogram of the training split |
| `task2/sweep.py` | runs the experiment phases as parallel processes |
| `task2/compare.py` | aggregates per-(seed, origin) rows, applies the tie rule, chooses the configuration |
| `task2/make_submission.py` | averages the final models, writes `forecast.csv`, `submission.txt`, `manifest.json` |
| `results/t2/` | all Task 2 results, regenerated by the commands below |

### Validation protocol
- **Split:** the last 12 × 168 observations (`time_idx` 41641–43656) are held out. Training windows end before 41641, and scalers are fit on the training rows only.
- **Scoring:** 78 forecast origins, one every 24 steps. A configuration's score is the mean over origins of the per-origin RMSE. MAE, sMAPE and bias are tracked too.
- **Comparisons:** every comparison uses 3 seeds. Two configurations are tied when their mean RMSE differs by less than 2 standard errors of the difference, and a tie keeps the base setting.

### Reproduce
```bash
pip install -r task1/requirements.txt pytest
python -m pytest -q tests                      # unit tests: decomposition, Auto-Correlation, masking, guards
python -m task2.eda                            # period recovery -> results/t2/eda.json, acf.pdf
python -m task2.data                           # naive baseline on the validation origins

# Each training script takes --mode smoke (a few windows, CPU, ~1 min) or --mode full.
python -m task2.sweep --phase exog    --mode full --jobs 6   # external-data ablation: none/past/future/both x 3 seeds
python -m task2.compare --stage exog
python -m task2.sweep --phase arms    --mode full --jobs 6   # input length, target transform, kernel, lr, width
python -m task2.compare --stage arms
python -m task2.sweep --phase confirm --mode full --jobs 6   # chosen configuration, seeds 3-4
python -m task2.compare --stage confirm                      # sets E* and the ensemble
python -m task2.sweep --phase final   --mode full --jobs 6   # refit on all rows for E* epochs
python -m task2.make_submission                              # results/t2/final/
```
The runs were made on one Colab L4 GPU, six processes at a time, in about 75 minutes.
